# Shiftwise 智慧自動排班系統

專為餐飲、零售、門市與其他服務業設計的 Streamlit 排班原型。系統會依據每日各班別需求，考量員工可上班時段、每週最高工時、最多連續上班天數與期望休假，產生可下載的週排班表。

目前已加入 SQLite 永久保存：員工資料會保存於 `shiftwise.db`，產生班表與儲存拖曳結果時會建立班表版本紀錄；重新啟動應用程式後，示範門市與最近班表仍可載入。

## 登入帳號（原型示範）

首次啟動可使用以下示範帳號：

| 角色 | 帳號 | 密碼 |
| --- | --- | --- |
| 管理者 | `admin` | `admin123` |
| 店長 | `manager` | `manager123` |
| 員工 | `staff` | `staff123` |

正式上線前請更換示範密碼，並將使用者管理改為邀請制或接入正式身分驗證服務。

權限行為：管理者與店長可修改排班規則、員工資料、尖峰需求與臨時請假；員工帳號為唯讀模式，只能查看目前的儀表板與班表。

員工帳號也可在總覽頁送出請假申請；管理者或店長核准後，申請日期會自動加入排班限制，重新排班時不會指派該員工。

員工也可送出換班申請，由店長或管理者核准／拒絕；總覽健康檢查會額外檢查每週工時與班次之間的最低休息間隔。

## 啟動方式

建議使用 Python 3.10 或以上版本：

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1

pip install -r requirements.txt
streamlit run app.py
```

啟動後開啟終端機顯示的網址，通常是 `http://localhost:8501`。

## 正式部署設定

### Email／LINE 通知

通知介面位於 `notifications.py`，不會把密碼寫入程式。部署到 Streamlit Cloud 後，請在 App settings → Secrets 填入 `.env.example` 中的 SMTP 與 LINE 變數。SMTP 建議使用 App Password；LINE 使用 Messaging API Channel Access Token。未設定時，排班核心仍可正常運作，只會回報通知尚未設定。

### Supabase 雲端資料庫

`supabase_schema.sql` 是雲端資料庫初始 schema，請在 Supabase SQL Editor 執行。完成後再將 `SUPABASE_URL` 與 `SUPABASE_KEY` 放入 Streamlit Secrets；正式切換雲端持久化前，需把本機 SQLite 資料匯入 Supabase 並確認 RLS policy。

### 網域與資安

Streamlit Cloud 的公開網址可直接使用；自訂網域需在網域 DNS 設定 CNAME 指向 Streamlit Cloud 提供的目標。正式上線前請更換示範密碼、啟用 GitHub／Streamlit MFA、限制 Supabase RLS、不要將 `.env`、`shiftwise.db` 或任何 Token 提交到 GitHub。

## 使用流程

1. 在左側設定排班週、每週最高工時、連續上班上限、班別時間與每日需求人數。
2. 在「員工資料」分頁輸入姓名、可上班日、可上班班別與期望休假。
3. 切換到「自動排班」分頁，按下「一鍵自動排班」。
4. 在「匯出班表」分頁下載 CSV 或 Excel。

員工分頁提供姓名搜尋與班別篩選；自動排班分頁也可依員工或班別過濾下方明細，日曆仍維持完整班表以確保拖曳調整不會遺失其他班次。

管理者或店長可在員工頁按「載入模擬團隊」，一次加入 8 位具備不同可上班日、班別與休假偏好的測試員工，方便驗證尖峰需求與請假補位情境。

## 尖峰與突發狀況

- 在左側「每日需求人數」中，每個日期與班別都有「基本需求」及「尖峰加派」欄位。尖峰加派會直接增加該班的需求槽位，系統會依照原有工時、可上班時段與連續上班規則尋找合適人力。
- 在左側「臨時請假／突發狀況」中，選擇日期、員工與原因後加入請假紀錄。重新按下「一鍵自動排班」時，該員工在指定日期不會被指派，系統會嘗試由其他符合條件的人員補位。
- 若備援人力不足，缺口會出現在排班結果下方的「未滿足需求」，方便主管進一步調整尖峰加派、工時上限或臨時請假安排。

## 排班規則

`scheduler.py` 使用可讀性高的限制式貪婪演算法：每個需求槽位只會指派給符合可上班日、可上班班別、每週工時、不可同日多班與連續上班限制的員工；在符合條件者中，優先避開期望休假，並平衡目前累計工時。無法滿足的需求會列在「未滿足需求」中，方便主管補排或調整設定。
